## 权限与判断

宿主适配结论是标准 Bundle 的 `direct` 路径；风险分级为 R2，商城保守权限等级为 `high`。保持现有 Host + Client 结构：Host 承担 QQ 工具和配置，Client 只提供挂载会话设置，避免将凭据交给浏览器。不在本次整改中改造代理服务、重写工具或更换卡片。

文件、网络、凭据和外部账号能力见 [SECURITY.md](../../SECURITY.md)。这些能力有实际用途，不能通过删除声明或改名伪装成低权限。源码结构审核、安装成功、功能使用、安全审计和商城准入是不同结论。

| 决策 | 目标和收益 | 成本 | 证据及重新考虑条件 |
| --- | --- | --- | --- |
| 保持现有实现 | 保留用户已验证的 QQ 功能 | 仍需高权限审阅 | 现有运行代码不变；宿主 API 变化时再考虑适配 |
| 补充版本范围声明 | 消除缺少 DSH 范围的声明问题 | 只声明范围，不承诺额外验收 | manifest；实际支持范围变化时更新 |
| 披露权限边界 | 让用户与商城了解实际访问范围 | 不符合无权限自动批准策略 | SECURITY.md；只有实际能力变化时才调整 |

## 下一步与状态

整改随 0.9.2 提交并推送到默认分支，GitHub Release 附件也包含本记录；商城会按新的固定 Commit 自动复检。npm 发布仍由维护者单独执行。未向 DSH STORE 提交或回复 Issue，也未完成独立安全审阅。商城仍可能保留 `blocked`，或经专项审阅采用 `user-reviewed`；补充声明本身不能保证解除拦截。

本次不再重复测试功能；用户的手工测试不被写成缺失的安装、启动、卸载或回滚证据。官方 Desktop UI、逐工具回放、真实 QQ 写操作和未测 DSH 版本保持未验证。
